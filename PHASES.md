# Implementation phases

## Bangladesh extension

| Phase          | Delivered changes                                                                                                         | Verification                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1. Inspect     | Reused shared article/category relations, Express services, RSS parser, worker lease, cards, bookmarks and theme provider | Architecture reviewed before edits; no replacement app                                |
| 2. Sources     | `packages/db/src/bangladesh-sources.ts`, six verified RSS sources, disabled official/API entries, host allowlist          | Live feed checks and documented limits in `BANGLADESH.md`                             |
| 3. Database    | Migrations `000004`–`000007`: scoped sources/categories, regional scores/status, review state, Unicode search and indexes | `npm run db:migrate`; all 164 baseline IDs and attributions preserved                 |
| 4. Classifier  | `processors/bangladesh.ts`, two evidence checks, English/Bengali patterns, reasons and review status                      | Positive, negative, ambiguous and keyword-trap tests                                  |
| 5. Collection  | Bangladesh RSS registrations and optional licensed adapter inside the existing worker, separate relevance counters        | Real first pass: 224 candidates, 11 accepted; no second scheduler                     |
| 6. API         | Scoped router, shared catalog/query services, accepted-only visibility, pagination, Dhaka date bounds and indexed search  | Regional and original global PostgreSQL integration suites                            |
| 7. Frontend    | `/bangladesh`, navigation, reusable cards, Bengali font, language/source/date/topic filters, disclosures and local times  | Desktop/mobile browser flows with real English/Bengali stories                        |
| 8. Integration | Classifier, API, UI, review persistence, duplicates, source outages, private-candidate protection and global regressions  | `npm test`; `npm run test:integration`; both browser scripts                          |
| 9. Production  | Existing service topology retained; Docker administration scripts and optional API env settings included                  | Production builds/runtime; Compose/Render schema checks; deployment limits documented |

## Original application

All ten requested phases have source deliverables. Commands run from the repository root after `npm ci` and `.env` configuration. Actual checks and infrastructure limits are recorded in [VERIFICATION.md](VERIFICATION.md).

| Phase                  | Created / changed                                                                                                                                              | Run and verify                                                                                                                              |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Monorepo            | Root package/lock files, strict TypeScript, three `apps/` workspaces, shared/db packages, Vite/Tailwind, tsup                                                  | `npm ci`; `npm run typecheck`                                                                                                               |
| 2. Database            | `prisma/schema.prisma`, four SQL migrations, seed, optional local PostgreSQL helper                                                                            | `npm run db:local` in another terminal; `npm run db:migrate`; `npm run db:seed`                                                             |
| 3. Ingestion           | Separate publisher adapters, RSS/Atom and HN normalization, optional GNews, bounded HTTP client, classification and transactional deduplication                | `npm run collect`; inspect collection logs and source/article tables; parser tests in `tests/pipeline.test.ts`                              |
| 4. Worker              | Dedicated startup/cron process, source next-poll times, retries/cache/quota handling, PostgreSQL lease, heartbeat and recovery                                 | `npm run dev -w @techpulse/worker`; check `CollectionJob`, `CollectionLog` and `/api/health`; second worker exclusion is integration-tested |
| 5. API                 | Express routes, combined filters, stable ordering, pagination, Zod validation, safe errors, CORS, rate limits, logs and bounded caching                        | `npm run dev -w @techpulse/api`; `curl http://localhost:4000/api/health`; `npm test` and integration tests                                  |
| 6. Dashboard           | Responsive editorial layout, real article cards, featured section, rankings, topics, source status, themes, placeholders, loading/error/empty states           | `npm run dev`; open http://localhost:5173 at desktop/tablet/mobile widths                                                                   |
| 7. Reader features     | Server search, URL-persisted source/topic/date/language/region filters, newest/trending ordering, pagination, localStorage bookmarks, source page              | Search with Enter; combine filters; save a story and reload `/saved`; inspect calculated-rank explanation                                   |
| 8. Validation/security | Vitest, Supertest and RTL tests, PostgreSQL integration suite, SSRF host and redirect checks, XML entity rejection, runtime env validation, CSP and safe links | `npm test`; `npm run test:integration`; `npm run typecheck`                                                                                 |
| 9. Deployment          | Dockerfile, Compose services, Render blueprint, Vercel frontend config, health helper, CI and operations guide                                                 | `npm run build`; follow `DEPLOYMENT.md` on the selected provider; local checks do not imply an external deployment                          |
| 10. Live verification  | Real six-source collection into PostgreSQL, API smoke checks, desktop/mobile browser checks, production-bundle smoke checks                                    | See `VERIFICATION.md`; reproduce with `npm run collect`, API requests, and the optional browser script                                      |

Optional future extensions, not implemented: authenticated bookmarks, semantic/AI event clustering, multilingual translation, analytics, distributed API rate limiting and full-text relevance search. These are not required for the included reader, worker or API to run.
